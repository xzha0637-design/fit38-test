How to understand an account risk result

This page explains what Signal Review checks, how to read its result, and why a person must make the final judgement.

This reference page does not change your assessment. After reading it, select Return to assessment. Your current account result will still be available in this browser tab.

Automated enforcement is prohibited. A result must not suspend, restrict, report, or otherwise act on an account.

Start here

How to use this page

No machine-learning knowledge is required. Read these three short sections before using a result to decide what needs closer human review.

  1. See what is checked Understand the public account information used by the tool.
  2. Read the result correctly Use the score and risk level for prioritisation, not proof.
  3. Check when to be cautious Look for missing data, changing behaviour, and false alarms.

1 · Public account information

What this tool checks

Signal Review compares basic public account signals that are available in the offline project data. These include account age, follower and following counts, posting activity, and whether common profile fields are present.

It does not read private messages, decide whether profile text is true, or inspect the account's full relationship network. No single item proves that an account is automated or harmful.

2 · Score and risk level

How to read the result

  • Risk score: use it to compare which accounts may need attention first.
  • Low, Medium, or High: this is a review priority band, not a bot/human label.
  • Contributing factors: these show which available signals moved the score up or down.
  • Data-quality warning: check whether important fields are missing before relying on the result.

A risk score is a ranking signal, not a probability. A score of 91% does not mean there is a 91% chance that the account is a bot.

3 · Human judgement

When the result needs extra care

When account behaviour changes

Patterns on Twitter/X can change after the project data were collected, so current accounts may behave differently.

When the account population is different

Results may be less reliable for accounts that differ from those represented in the two bundled datasets.

When a legitimate account looks unusual

High activity or uncommon follower patterns can raise a score even when an account is legitimate.

When useful evidence is missing

The tool does not include full network relationships, private data, or the meaning of posts and profile text.

Your review is the decision. Never use this result as proof or as a reason for automatic reporting, suspension, or moderation.

Public-data feature schema

What the 12 public-data features mean

The model uses these signals together. Training labels are not shown in the account selector or assessment interface.

Account age
Days since the public account creation date.
Follower count
How many accounts follow this account.
Following count
How many accounts this account follows.
Follower-to-following ratio
The balance between audience and connections.
Tweet count
The recorded total number of public posts.
Posting frequency
Average public posts per day over the recorded account age.
Description length
Number of characters in the public biography, not its meaning.
Username length
Number of characters in the public username, not its wording.
Profile completeness
How many required model fields are available; below 50% stops scoring.
Verified status
Whether the public verified flag is present.
Default profile image
Whether the platform's default profile image is still used.
Description present
Whether a public biography is present.

Full follower/following graph features, graph topology, private data, and content-semantic features are excluded.

Available evaluation evidence

Held-out test split: 5,929 records. At the recorded XGBoost binary threshold of 0.10:

F1
0.5859
Precision
0.4158

0.9915
Calibration evidence
Low/Medium/High boundaries were selected on a separate validation split of 5,929 records (recorded validation mean cost: 0.266149). No formal probability-calibration or reliability metric is available.

Plain-language reading

  • F1: one summary of the balance between precision and recall.
  • Precision: about 42 of every 100 accounts assigned the recorded positive class matched the positive label in this test data.
  • Recall: about 99 of every 100 positive-labelled accounts in this test data were found at the recorded threshold.

Recorded limitations and unsupported uses

  • Cross-dataset limits: performance has not been validated on an independent external dataset.
  • Prevalence shift: different bot/human proportions can change precision and error rates.
  • Concept drift: account behaviour and platform conventions can change over time.
  • False positives: legitimate accounts may receive elevated scores.
  • Excluded graph evidence: coordinated-network signals cannot be inferred from this feature set.

Do not use the output as proof that an account is automated, harmful, fraudulent, or policy-violating. Automated moderation, sanctions, reporting, and enforcement are prohibited.
